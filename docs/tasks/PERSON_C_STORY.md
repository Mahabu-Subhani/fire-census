## Phase 1. Sat 10:15 to 13:00: structure

### 1.1 Open the project page

- [ ] Team page, Project tab, Edit. Turn the edit lock on while you work.
- [ ] Put a rough first line in **every** field and click Save Progress. This

### 1.3 The pitch

- [ ] Write the one-sentence pitch: who it is for, what it does, why it can be
      trusted. Get both teammates to agree to the wording.
- [ ] Write the problem in two sentences a non-expert understands (the newer
      satellite sensor sees more fires, so combined records show a jump that
      is not real).

### 1.4 Demo storyboard

Use the official timing from the Submission Guide:

| Time | Content |
|---|---|
| 0:00 | Your name and the team name |
| 0:02 | The challenge and why we chose it |

| 0:10 | How it works: show the app, name the NASA data |
| 0:20 to 0:30 | What it could do for people in the future |

- [ ] Sketch each shot. The strongest image is the raw record's jump at 2012
      disappearing when the switch is flipped.
- [ ] If slides: plan at most 7, including title and intro. Slides must show the
      team name, member names and the challenge.

### 1.5 Real-world grounding

agreed by all three.

## Phase 3. Sat night to Sun 12:30: evidence and demo

### 3.1 Results, honestly

- [ ] Get `meta.json`, the ladder table and all figures from Person A.
- [ ] Write one sentence per test: what it checks, the result, pass or fail.
      Include any that failed and what that means.
- [ ] Write the "Limits" section from `docs/APPROACH.md`, "Known limits".

### 3.2 Project page fields

| Field | What to write |
|---|---|
| Project Name | The name the team chose |
| High-Level Summary | What we built, how it addresses the challenge, why it matters. About 150 words. Lead with the user and the problem |
| Link to Project Demo | Public link to the video or slides |
| Link to Final Project | The live app link. Mention the repo link in the description |
| Detailed Description | What it does; how it works (the two fixes, the tests); benefits; what we hope to achieve; tools and languages used. Use headings and the figures |
| Use of AI | From `docs/AI_USE.md`: which tools, for what, and what the team decided itself. Truthful and specific |
| NASA Data | FIRMS, with the exact product names for MODIS and VIIRS and the satellites used |
| Partner Data and References | Everything in `docs/REFERENCES.md`. Mention CONAE's hotspot viewer if we cite it as context |

- [ ] Each field written, read aloud once, and saved.
- [ ] Map the text to the five criteria: one clear paragraph each for Impact,
      Creativity, Validity and Relevance. Do not use those words as headings;
      make sure the content is there.
- [ ] Add images to the page (up to 10 MB each): the raw jump, the calendar,
      the ladder table.

### 3.3 The demo

- [ ] Record from the live app, not a mock-up.
- [ ] Time it. A video over 30 seconds makes the project ineligible. Aim for 28.
- [ ] English narration, or English subtitles if spoken in another language.
- [ ] No one under 18 visible or audible. No NASA logos. No copyrighted music.
- [ ] If any image or clip is AI-generated, it carries a visible watermark.
- [ ] Upload to a public host. Open the link in a private window to confirm.

### 3.4 If there is a live local pitch

- [ ] Prepare a version of the right length with the same story: problem, the
      switch, the evidence, the limits, the future. Rehearse it twice.
- [ ] Prepare answers to: how is this different from a simple ratio; what does
      it not do; how was AI used.

**Checkpoint Sun 12:30.** Demo recorded and under the limit; page text complete.
